Installing GearOut

GearOut runs as one Docker Compose stack per institution: the web app, a background worker, PostgreSQL, Redis, MinIO for images, and Apache in front for TLS. One command sets all of it up.

Requirements

  • A Linux server with Docker Engine and the Compose plugin.
  • 2 vCPU, 4 GB RAM, 20 GB disk. A department of a few hundred students fits comfortably.
  • A public hostname that resolves to the server, with ports 80 and 443 open.
  • Node.js 22 or newer on the server, only to run the installer.
  • The sign-in details from your identity team.

The one command

git clone https://github.com/AURA-Lab-SIUE/gearout.git
cd gearout
npm run build:cli
node dist/cli.js init

init asks its questions, shows a summary, then writes the configuration, builds and starts the stack, applies the database migrations, seeds your tenant, and requests a Let's Encrypt certificate. It ends by printing the sign-in URL and the first administrator API token, shown exactly once. To see what it would write without changing anything, add --dry-run. To run it unattended, put the answers in a JSON file and pass --answers file.json --yes.

Passwords and secrets (database, session signing, field encryption, storage) are generated for you. Rerunning init never deletes data: it asks before overwriting the configuration file and leaves users, equipment, and reservations alone. Upgrades are a pull, a rebuild, and the migrations, documented in the runbook that ships with the product.

Four ways to receive it

Every option delivers the same software, built to your specification, validated end to end on an empty instance, and handed over with a client-IT note. You load student data only after acceptance.

Choosing: managed for a program with no server of its own; the self-hosted image for an institution that already runs Docker somewhere; sealed media for a download-averse or air-gapped environment; the appliance for a department that wants the cage on one box in the closet and no cloud footprint at all. Sign-in setup

The setup guide for Entra ID, Google Workspace, and SAML through SSOReady, including the exact redirect URI for each and a ready-to-send request for your identity team, ships with the product at docs/sso.md. Your identity team registers one redirect URI per method.
